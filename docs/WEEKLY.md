# Недельный обзор

[Скачать пустой Excel-шаблон](https://barsuk-box.github.io/ecobox-dashboard/templates/ecobox-weekly-template.xlsx). Пять листов: параметры и инструкция, лиды, заказы, производство, ожидаемые оплаты. Заполненный файл передаётся для проверки и импорта вместе с основной таблицей; автоматическая загрузка через сайт не предусмотрена.

В шаблоне заполняются начало и конец полного периода, дата среза, подтверждения полноты лидов/событий и база сумм. Регистры — подмножество основной очереди; блины — отдельный портфель с пояснением состава. Реестр ожидаемых оплат содержит отдельные отметки крупной оплаты и допустимости публикации. Импорт должен учитывать обе отметки, не публиковать непроверенные подробности и не считать пустое поле нулём. ID заказов и платежей уникальны; ID лида может повторяться в разных заказах. В Excel нет демонстрационных фактов.

Неделя: понедельник–воскресенье. Для каждого показателя конец периода — минимум из воскресенья, последней даты его данных и даты среза. Сопоставляются одинаковые дни предыдущей недели. Фильтр месяца не обрезает недели на границе месяцев. Суммы считаются по дневным записям; расхождения с ручной месячной сводкой не распределяются искусственно.

Отсутствие чисел — «Нет данных»/«—», записанный ноль — 0. Процент изменения при нулевой базе не рассчитывается. Полнота каждого календарного дня источником не подтверждена. Отгрузка после даты среза исключается из недельного факта, даже если месячный раздел сохраняет её по исходной таблице.

Регистры: «Реготоп» в заявках и «регистры» в денежных листах; «Блины» — отдельное направление. Обе строки входят в общий денежный итог. Дополнение «Блины» из Pipeline!E8 показано отдельно от основного остатка производства; его состав не объявляется подтверждёнными заказами в производстве. Разбивки основного производства по регистрам в текущем Excel нет.

## Производство

История сохранена из ранее опубликованных версий: 23.09 (87eef3d), 01.10 (f8a7df3), 08.10 (8e522a8). Это остатки на конкретные даты, не недельный выпуск. Срезы не суммируются, не интерполируются и не переносятся на воскресенье. При обновлении сохранять предыдущий срез в `src/data/weekly-inputs.json`; новая дата берётся из основного JSON.

## Какие поля нужны в новом файле

| Данные | Поля |
| --- | --- |
| Лиды | устойчивый ID лида, дата создания, направление |
| Заказы | устойчивый ID заказа, ID лида, направление, сумма заказа, дата подписания, дата первой оплаты |
| Производство | дата среза, количество и сумма основной очереди; регистры отдельно; «блины» отдельно с пояснением состава |
| Крупные ожидаемые оплаты | безопасное обозначение заказа, сумма ожидаемого поступления, ожидаемая дата, препятствие, следующий шаг, отметка «крупная» |

Подписанные и оплаченные заказы считаются отдельно по дате события, уникальному ID заказа. «Оплачен» в этой версии — появилась первая оплата; сумма заказов с оплатой не равна сумме поступлений. Для полной оплаты потребуется отдельная дата полного погашения. Конверсия — доля уникальных лидов выбранной недели, у которых к срезу есть связанный подписанный/оплаченный заказ. Несколько заказов одного лида дают одну конверсию. Сравнение когорт имеет разный срок наблюдения, что отмечено в интерфейсе.

## Подключение дополнительных данных

`src/data/weekly-inputs.json`: `productionSnapshots` (date,count,amount,registersAmount,pancakesAmount); `leadCohort` (id,createdAt); `orders` (id,leadId,amount,signedAt,paidAt); `expectedPayments` (id,label,amount,dueDate,blocker,nextStep). Даты ISO YYYY-MM-DD, отсутствующие значения null. `salesCoverage: {from,through}` добавляется только при подтверждённой полноте реестра лидов и событий на указанный период; без неё нули и конверсия не отображаются как факты. Проверять уникальность ID, ссылки заказов на лидов, хронологию событий, суммы и полноту покрытия при загрузке.

В `expectedPayments` включать только отмеченные владельцем крупные ожидаемые оплаты; автоматический порог без согласования не придуман. Список относится к текущему срезу, не к выбранной исторической неделе. Просрочка определяется относительно среза. Пока реестр отсутствует, показано пустое состояние с перечнем нужных полей. Новые поля не заполняются агрегатным прогнозом.

Публичный сайт: использовать обезличенные обозначения. Перед публикацией нового реестра отдельно проверить допустимость раскрытия препятствий, шагов и сведений о заказах; прежнее разрешение на агрегаты не расширяет его на персональные или закрытые договорные данные.
